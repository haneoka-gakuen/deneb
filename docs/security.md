# Security model

Deneb treats projects, assets, runtime bundles, plugin locks, and plugin output
as untrusted inputs.

## Enforced boundaries

- Project bytes and JSON structure are bounded before semantic processing.
- Strict envelopes reject misspelled fields; flexible command payload is
  confined to JSON values.
- Local paths reject roots, parent/current segments, empty segments,
  backslashes, drive separators, and control characters.
- Asset canonicalization catches a project symlink that resolves outside the
  project root.
- Runtime directories reject every symlink and enforce file-count/byte limits.
- Release builds reject remote project assets; local files and data URIs are
  copied into a bounded, content-addressed offline store.
- Authored asset hashes, runtime integrity entries, and locked plugin hashes use
  lowercase SHA-256.
- Runtime and Deneb license/notice files are preserved in both directory and
  archive outputs; a runtime with no conventional legal file emits a warning.
- Output cannot be a filesystem root or an ancestor of the project file.
  Forced replacement stages first, keeps a temporary backup, and restores it
  if the final rename fails.
- Generated Web uses a restrictive CSP. Electron disables Node integration,
  enables isolation/sandboxing, denies popups, and blocks external navigation.
  Tauri grants only `core:default`.
- Deneb executes build plugins through a Wasmtime Component host with no WASI
  linker and no socket, clock, environment, filesystem, or process imports.
  The normal build never grants `network`, `process`, or `publish`.
- Component metadata must exactly match the manifest and lock. Calls receive a
  64 MiB linear-memory ceiling, 50 million fuel units per boundary call, and
  bounded wall time. File count, generated bytes, and diagnostics are enforced
  cumulatively for the build-scoped session.
- Project and asset reads are capability checked and remain under the
  canonical project root. Generated paths are portable relative paths under a
  plugin-specific hashed namespace; duplicates and traversal are rejected.
- Transform output is RFC 7396 JSON Merge Patch. The merged project is strictly
  reparsed and semantically revalidated, and locked plugin identities cannot be
  changed.
- Project assets, ordinary runtime directories, plugin artifacts, generated
  plugin output, and copied legal sidecars are scanned with an explicit
  distribution scope. Known SDK/Core/Framework and binary runtime payloads are
  rejected from ordinary public output, while provider names in public
  code-only adapters and notices are allowed.
- Authored model, motion, atlas, and skeleton formats are project content, not
  runtime SDKs. Deneb therefore does not blacklist their extensions or file
  signatures; the project publisher remains responsible for the rights to
  distribute those assets.
- Separately licensed multi-file runtimes enter only through lock-declared
  external-runtime requirements and a local artifact-map attachment. Copying
  additionally requires `--allow-private-external-runtimes`, exact per-file
  SHA-256 values, an application-bound `application-private` declaration, and
  a hashed license receipt with an explicit acknowledgement. Symlinks, partial
  manifests, remote acquisition, and unselected attachments fail closed.
- License receipts are verified but not copied. Any output carrying an
  external attachment is marked `publiclyRedistributable: false` in its build
  manifest, target metadata, external-runtime index, and SBOM.

## Trust not provided by Deneb

Deneb does not make remote HTTP assets immutable, verify publisher identity
without a configured signature policy, audit a Vega runtime's JavaScript,
create signing credentials, or turn a development build into a store-approved
release. A checksum establishes bytes, not authorship.

Deneb also cannot decide whether a license permits a particular application,
platform, audience, or expandable tool. The attachment acknowledgement records
the publisher's decision and enforces byte/application binding; it is not a
license grant or legal opinion.

Run dependency review in addition to the repository tests:

```sh
cargo deny check
cargo audit
```

CI uses the committed `Cargo.lock`; release automation should emit an SBOM and
sign the final manifest/archive without rewriting them.

For private vulnerability reports, follow the process in the repository
[SECURITY.md](../SECURITY.md).
